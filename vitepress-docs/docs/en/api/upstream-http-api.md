## Requests and authentication

- Base URL: `https://<worker-or-proxied-domain>`; JSON body: `Content-Type: application/json`.
- `x-lang`: `zh` / `en`.
- `x-custom-auth`: site password when configured; `/open_api*` and `/telegram/` bypass this global check.
- `/api/*`: `Authorization: Bearer <mailbox credential>`; exceptions: `/api/new_address`, `/api/address_login`.
- `/user_api/*`: `x-user-token`; exceptions: `open_settings`, `register`, `login`, `verify_code`, `passkey/authenticate_*`, `oauth2*`. `DISABLE_USER_SYSTEM` can block this entire group.
- `POST /user_api/bind_address`: requires BOTH user token and mailbox credential.
- `/admin/*`: `x-admin-auth`, or valid `x-user-access-token` with admin role; also subject to admin IP allowlist. `DISABLE_ADMIN_PASSWORD_CHECK` changes enforcement.
- `x-user-access-token` is a role token, NOT interchangeable with `x-user-token` or mailbox credentials.
- `/external/api/send_mail`: mailbox credential in JSON `token`; not an anonymous sending endpoint.
- Telegram Mini App: signed `initData`; bot webhook passes updates to the Telegram library. Do not infer mailbox JWT protection from `/telegram/` paths.
- `/redeem_api/*`: redemption-specific body validation and rate/access controls; not covered by user/mailbox JWT middleware.
- `/open_api/a/:mail_id/:index/:expires/:signature`: signed attachment URL; public routing does not remove signature/expiry validation.
- Login endpoints `/open_api/site_login` and `/open_api/admin_login` accept hashed `password` and optional `cf_token`, return `{success:true}` rather than issuing a session JWT.
- Errors are not uniform: JSON, plain text, and endpoint-specific responses coexist. Check status and Content-Type; do not assume all failures are JSON.
- Global DB/JWT configuration checks still apply. Webhook, S3, Telegram, sending, deletion and user creation depend on feature configuration.
- `/` and `/health_check` are health routes, but ASSETS middleware can intercept non-API paths. Unmatched requests fall through to 404; CORS middleware handles preflight. Email/scheduled Worker events and SMTP/IMAP proxy protocols are not HTTP routes.

## curl

```bash
# BASE: deployed Worker URL; MAILBOX_TOKEN: mailbox credential
# Add x-custom-auth when required by the deployment.
curl "$BASE/api/mails?limit=20&offset=0"   -H "Authorization: Bearer $MAILBOX_TOKEN"

curl "$BASE/api/mail/123"   -H "Authorization: Bearer $MAILBOX_TOKEN"

curl -X PATCH "$BASE/api/mails/123/read"   -H "Authorization: Bearer $MAILBOX_TOKEN"   -H 'Content-Type: application/json' -d '{"isUnread":false}'
```

A missing mail may return JSON `null`, not 404. Read status requires `ENABLE_MAIL_READ_STATUS` and a boolean `isUnread`.
